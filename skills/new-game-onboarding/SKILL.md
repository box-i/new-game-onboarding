# 新游接入全流程管理 (/new-game-onboarding)

## 概述

你是游戏平台PM，负责公司所有新游戏从首次对接到正式上线的全流程平台侧接入管理。

这个 skill 帮助你：
1. **识别游戏信息** — 解析 gate 编码、确认游戏类型和特殊需求
2. **判断当前阶段** — 确定游戏所处阶段，跳过已完成环节
3. **收集项目信息** — 结构化表单，逐项确认
4. **输出跟进文档** — 自动生成阶段任务清单和待办项
5. **提醒关键节点** — 各阶段的配置要点和常见坑

---

## 工作流程

### Step 1：识别游戏基本信息

#### 1.1 Gate 编码解析

Gate 是游戏的唯一标识，格式：

```
gate = 发行方案码 + 项目代号 + 发行地区码 + 代理商码
```

**发行方案码：**

| 编码 | 含义 |
|:---|:---|
| `p2` | 端游国服自营 |
| `p3` | 端游海外自营 |
| `p4` | 端游海外代理 |
| `p5` | 端游国服代理 |
| `m2` | 手游国服自营 |
| `m3` | 手游海外自营 |
| `m4` | 手游海外代理 |
| `m5` | 手游国服代理 |

> 代理 = 第三方发行。运营 = 我方产品的形式。

**发行地区码（常见）：**

| 编码 | 地区 | 编码 | 地区 |
|:---|:---|:---|:---|
| （省略） | 中国大陆 | `glo` | 全球 |
| `tw` | 港澳台 | `eu` | 欧盟 |
| `au` | 澳新 | `us` | 美加 |
| `me` | 中东 | `ru` | 俄罗斯 |
| `jp` | 日本 | `kr` | 韩国 |
| `in` | 印度 | `id` | 印度尼西亚 |
| `ph` | 菲律宾 | `vn` | 越南 |
| `th` | 泰国 | `my` | 马来西亚 |
| `tv` | 试玩版本 | | |

**示例：**
- 梦想3手游国服自营版：`m2` + `k8` + 中国大陆（省去）+ 自营（省去）= **m2k8**
- 某手游海外代理东南亚版：`m4` + `xy` + `th` + 代理商码 = **m4xyth{代理商码}**

> 规则：发行地区为中国大陆时省去地区码，自营时省去代理商码。

#### 1.3 海外项目附加确认（仅 p3/p4/m3/m4 触发）

> Gate 前两位为 `p3`/`p4`/`m3`/`m4` 时，自动追加以下两问：

```markdown
## 海外项目附加信息

**1. 单机还是网游？**
- [ ] 单机（Steam 等平台发行的独立游戏）
- [ ] 网游（有服务端，长期运营）

**2. 运营主体是什么？**（可多选提示）
- [ ] dequ
- [ ] delan
- [ ] yijoys
- [ ] LC
- [ ] 其他新增主体：___________
```

> 单机项目的后续处理与网游有差异——例如游客登录链路、充值策略、账号绑定方式等，需要根据运营主体确定合规和数据存储方案。
>
> **🔀 特殊分支：海外端游 + 单机 + LC 主体**
> 如果项目同时满足以下三个条件：海外端游（`p3`/`p4`）、单机、运营主体为 LC，则走简化流程：
> - ❌ 无版署审核阶段，改为 **Steam 提审**
> - 前期信息收集（Step 3）和后台配置（Step 4）不变
> - 正式上线阶段充值素材需项目提供，尺寸标准找旧梦
> - 充值验收测试用例：在线文档 → 技术工程中心 → 账号中心 → 日常事务 → AI使用 → **旧梦skill-测试用例** → **LC** 页签
> - 打折测试有疑问可查阅文档或直接找旧梦

### Step 2：判断项目当前阶段

```markdown
**当前阶段（单选）：**
{如果是 LC 特殊分支 → LC 项目无版署审核，阶段选项调整为：}
{正常项目：}
- [ ] DEMO 阶段
- [ ] 公司内评审阶段
- [ ] 版署审核阶段（提审中）
- [ ] 公司内测阶段
- [ ] 不付费对外测试阶段

#### 阶段判断逻辑

| 阶段 | 账号中心是否需要介入 | 后续动作 |
|:---|:--:|:---|
| DEMO | ❌ 不需要 | 记录信息，等待项目通过内审后重新对接 |
| 公司内评审 | ❌ 不需要 | 记录信息，等待项目通过内审后重新对接 |
| 版署审核 | ✅ 需要 | → Step 3 + Step 5（虚拟充值） |
| Steam 提审（🔀 LC 特殊分支） | ✅ 需要 | → Step 3 + Step 4（仅后台配置，无需虚拟充值） |
| 公司内测 | ✅ 需要 | → Step 3 + Step 4 + 测试礼金接入 |
| 不付费对外测试 | ✅ 需要 | → Step 3 + Step 4 + Step 6（账号/客服功能验证） |
| 付费对外测试/正式上线 | ✅ 需要 | → Step 3 + Step 4 + Step 6 + Step 7（充值接入） |

> 如果项目处于 DEMO 或公司内评审阶段，告知使用者："当前阶段账号中心无需介入。建议项目通过公司内评审后再来对接。已记录基本信息，届时可继续使用本 skill 接力。"

### Step 3：首次对接 — 收集项目信息（必做）

> 无论项目从哪个阶段首次来对接，以下信息都需要收集。

**核心原则：**
- **逐节引导，一次只问一个主题** — 不抛大表格，像聊天一样逐步确认
- **已知信息自动填入** — 从 Step 1 的 gate 解析结果自动推导（发行地区、端游/手游、自营/代理）
- **每节均可跳过** — 用户说"跳过"或"待确认"则继续，不影响流程
- **端游自动跳过不适用的问题** — iOS 提审、应用包名等
- **先记后汇** — 所有回答先记录，全部收集完后汇总展示确认

---

#### 对话节奏

**核心原则：**
- **按模块打包，不逐条追问** — 每次抛出一个模块（3-5 个问题），用户一次性回答，不需填的标注"跳过"即可
- **已知信息自动填入，不重复问** — gate 解析结果（平台/发行地区/自营or代理）直接写入，用户不用再答
- **每模块均支持跳过** — 用户说"跳过"或"下一节"则整节跳过
- **端游自动精简** — iOS 提审、应用包名等不适用项直接跳过不展示
- **先记后汇** — 所有回答先记录，全部完成后汇总展示让用户确认

### Step 6：不付费对外测试 — 账号类与客服类功能验证

> ⚠️ **项目到达"不付费对外测试"阶段时触发本步骤。**
> 核心目标：验证账号类功能是否正常运作，确认客服类功能选项是否已出现。

**什么是"选项"？**

> 在客服类功能（找回账号名、自助退款、开具发票、账号申诉）中，用户操作前需要先选择自己玩的是哪款游戏。这个下拉列表列出了所有已接入的游戏。
>
> **如果新游戏没出现在这个列表里 → 说明配置还没生效 → 需要先跟进配置。**
>
> 账号类功能（战盟登录、改密等）不需要查选项——它们是跟着游戏走的，配了就能用，直接测功能。客服类除自助退款外，只看选项有没有，不测功能。

#### 6.1 账号类功能验证

> 逐项实际操作，验证功能是否正常。无需检查选项——账号类功能跟着游戏走的，配了就能用。
>
> 测试用例库：国服手游 → **TSTDC-40** / 国服端游 → **TSTDC-39**

| 功能 | 正常 | 验证方式 |
|------|:--:|------|
| 战盟 PC 授权登录 | ⬜ | 打开战盟 PC 端 → 点击授权登录 → 选择游戏 → 扫码/输入账号 → 登录成功 |
| 战盟扫码登录 | ⬜ | 打开游戏登录界面 → 选择扫码登录 → 用战盟 App 扫码 → 确认 → 登录成功 |
| 改密踢下线 | ⬜ | 先登录游戏保持在线 → 去账号中心修改密码 → 返回游戏 → 被踢出并提示"密码已修改" |
| 封禁 | ⬜ | 在后台封禁测试账号 → 游戏内被踢出 → 再次登录提示"账号已被封禁" |
| 双重认证 | ⬜ | 开启双重认证 → 登录时触发验证 → 输入验证码 → 登录成功；关闭后不再触发 |
| 注销 | ⬜ | 提交账号注销申请 → 进入冷静期 → 到期后账号不可登录 |
| 角色心跳 | ⬜ | 登录游戏 → 后台查看角色在线状态是否正常上报（心跳间隔、离线判定） |
| 角色互通 | ⬜ | 同一账号在不同区服创建角色 → 确认各区角色数据独立、互不影响 |
| 修改昵称 | ⬜ | 在游戏内/账号中心修改昵称 → 确认新昵称生效 → 确认消耗道具/货币正确 |
| 假实名提醒 | ⬜ | 使用未实名账号登录 → 确认弹出实名认证提醒 → 不认证则受限进入 |

## 常见坑提醒

1. **每个环境都要单独配置** — 内测/外测/审核/正式，环境之间独立，不能复制。最容易漏的是审核环境。
2. **正式服 IMS 新建项目必须找春希** — 不能自己操作。
3. **角色重名规则是四选一必选** — 不选会导致后续创建角色逻辑异常。
4. **端游不需要 iOS 提审计划和应用包名** — 收集表单里直接填"不适用"。
5. **代理项目注意区分运营商** — 代理模式下部分配置由代理方完成。
6. **海外项目额外注意** — 多语言、合规（GDPR等）、游客登录链路、短信验证码国际成本。
7. **测试验收不要跳过战盟端 + 多易币** — 这条最容易漏，而且正式上线后用户投诉的第一来源常是这里。
8. **重要提示文本** — 战盟端充值时新增的重要提示文本（如充值比例、退款政策等）必须在测试阶段确认到位。

## FAQ：接入与测试中常见问题

### Q1：游戏客户端短信登录提示"短信发送验证码失败，请重试"

**大概率原因：** 短信白名单没有配置。

**排查步骤：**
1. 打开短信中心 → 短信中心配置 → 产品白名单
2. 检查当前环境的白名单列表中是否已添加该项目的 gate
3. 如果未添加，补充后保存，**内测、外测、正式服都需要单独检查**

> 审核环境不需要配置短信白名单。

> 这条是最常见的新游接入报错，90% 的情况都是白名单漏了。

---

### Q2：游戏内下单提示"购买项不合法"，或返回码 10103

**大概率原因：** IMS 中的购买项配置有误。

**排查步骤：**
1. 检查 IMS 中该环境的购买项 ID 是否与客户端请求一致
2. 检查下单网关是否正确配置
3. 如果是安卓/iOS 内购，确认购买项是否已在对应渠道配置（参考文档：https://oa.doc/kms/005qep）

> 返回码 10103 基本等于"IMS 不认识你传过来的这个购买项 ID"。

---

### Q3：充值中客服系统需要配置大客户标识

**容易遗漏的点：** 大客户标识是单独的配置入口，不在常规充值接入清单里。

**需要确认：**
- [ ] 项目是否需要大客户标识功能（通常都会需要）
- [ ] 如果需要，在客服系统中单独配置，**不要等上线后才发现没配**

> 这个配置项不在 Step 7 的 8 项验收清单中，因为它是客服系统侧的独立配置。但上线后大客户充值走了普通通道会很麻烦，建议对外测试前主动跟项目确认。

### Q4：限号测试的两个坑

**坑 1：添加白名单账号是覆盖，不是追加。**

限号测试功能添加账号时，**配置会覆盖前一批**，不是增量添加。

- ❌ 错误做法：第一批配置了 a、b；第二批只写 c、d → 结果：只有 c、d 能进，a、b 被踢出
- ✅ 正确做法：每次添加时把之前所有账号都写上：a、b、c、d

**坑 2：测试时间到了，没有停用按钮。**

限号测试的结束时间到了之后，功能**不会自动停用**——没有开关、没有按钮。

- 解决办法：联系游戏服务端同学，通过**热更取消 `trial` 传参**来手动关闭
- 建议在测试开始前就跟服务端同学约定好："到时间后你热更关 trial 参数"
